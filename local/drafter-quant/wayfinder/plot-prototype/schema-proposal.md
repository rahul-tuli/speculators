# Plotting proposal — awaiting human review

This throwaway prototype contains **synthetic data only**. No checkpoint was run and no measured performance or acceptance result is claimed. `synthetic_layout_data.csv` supplies illustrative acceptance observations, not the full production schema below. Other preview panels use explicitly synthetic values in `prototype.py`.

## Proposed figure set

- **A (recommended lead):** absolute acceptance length by calibration recipe and quantization scheme, with one panel per SPEED-Bench configuration. Show BF16-drafter reference, all three evaluation repeats, their mean and range. Use a common 1–8 acceptance-length axis for seven draft tokens. Acceptance length is `1 + A / D`.
- **C (recommended companion):** Gaussian/real recipe pairs within each scheme, with real-minus-Gaussian differences in the companion table. Effects describe complete calibration recipes. Include each round's contrast, its mean and range in the final contrast table; do not infer contrast uncertainty from unpaired endpoint ranges.
- **B (supplement):** absolute acceptance-length changes against the corresponding BF16-drafter evaluation round. No prompt-level pairing or confidence-interval claim.
- Supplementary pages: accepted-token fraction `A / P`, per-position `A_i / D` (all draft events), and category/subcategory detail using the same layouts. Zero denominators remain undefined, and target-only acceptance is not applicable. Display positions 1–7 with an explicit mapping from raw zero-based indices.
- Seed 0 first; later seeds get separate panels with repeat mean/range in each. No single bar merging seeds and evaluation repeats. BF16/target-only references have no calibration seed; link actual reference runs instead of inventing seed replicates.
- Performance pages: single-request end-to-end latency at concurrency 1; throughput curves at concurrency 1, 8, 32, 128; ratios against **separately named** BF16-drafter and target-only references; throughput-versus-acceptance panels at one shared operating point. Also retain TTFT and ITL supplementary pages. Figure previews show the layout; final figures must show every repeat and descriptive range.
- Separate pages for model pair, hardware, backend/treatment, calibration seed, configuration and category scope. Always label NVFP4 on H100 as W4A4 emulation. Native Blackwell gets fresh same-hardware references and separate pages. Do not draw lines across missing load points or compare different devices as a speedup.

## Proposed aggregation and metric rules

1. Configuration summaries pool **raw counters within each repeat** over its complete, disjoint category coverage: `1 + sum(A)/sum(D)`, `sum(A)/sum(P)`, and `sum(A_i)/sum(D)`. Then display three repeat ratios and their arithmetic mean and min–max. No equal-category average by default. Publish every category separately, since pooled counters weight draft events and can hide category effects. These weights can differ across arms; call the result pooled observed acceptance, not a fixed category-standardized effect.
2. Never pool across configurations, loads, hardware, calibration seeds, or overlapping subset manifests. If a required subset is missing, show an incomplete summary with no numeric pooled result. A measured zero remains zero. Unsupported, failed, incomplete, not-run, and not-applicable have different status/reason values; no imputation.
3. Compare complete matched rounds with identical model pair, target, hardware allocation, workload manifest, load, decoding and warm-up protocol. Preserve the intended scheme/recipe/backend differences as treatment attributes. Compute real-minus-Gaussian and quantized-minus-BF16 differences within evaluation round, then mean/range of those differences. If a paired run is missing, show the available individual results and mark the contrast incomplete; never silently summarize two rounds as three.
4. **Proposed primary throughput:** successfully generated output tokens divided by the measured wall-clock interval, in tokens/s. Retain request success/failure counts; failed/incomplete coverage invalidates the comparison point. Within each configuration, a combined serial-subset summary is `sum(output_tokens)/sum(measured_seconds)`, labelled **serial-subset pooled throughput**; do not describe it as a jointly mixed workload. Publish category throughput separately. Do not average rates or medians. If intervals are not available, leave this metric missing rather than substitute GuideLLM's median rate.
5. **Proposed primary latency:** median successful-request end-to-end latency within each run, with all repeats plus mean/range of those medians. Configuration summaries recompute the median from the concatenated request records of complete, disjoint subsets, never from category medians. Record output lengths and describe results as end-to-end performance under common stopping controls, not normalized equal-output decode cost. TTFT is time to first token. Keep the current GuideLLM ITL metric as a supplementary statistic, explicitly named **token-weighted median request-average ITL**; it is not median individual token gaps and is not GuideLLM's TPOT field.
6. Throughput ratios are `arm/reference`; latency speedups are `reference/arm`. Use named reference run IDs for the same evaluation round; aggregate the three round ratios, not the ratio of repeat means. Raw values always accompany ratios. A target-only run has no acceptance coordinate in the speed/acceptance scatter.
7. Every speed/acceptance point comes from the same workload/load/measurement interval. Never copy acceptance from a whole sweep or concurrency 1 into another load. Show all three paired repeat points and marginal ranges without implying a confidence ellipse or independent samples.
8. Descriptive ranges are not confidence intervals. No equivalence verdict or 2% threshold. Preserve provenance limitations from the calibration and hardware decisions in final captions/report.

## Proposed normalized CSV bundle (schema version 1)

The following is a plotting interchange contract for the evaluation-record and execution tickets, not a requirement to replace their internal storage. Publish UTF-8 CSV with headers, explicit units, blank numeric cells for undefined values, and explicit status/reason. JSON manifests carry bulky identities. A validated adapter may populate these tables from canonical run records; never guess identity from filenames alone.

| File / grain                                                    | Required fields                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `runs.csv` — one row per actual measured run                    | `schema_version, run_id, comparison_round_id, phase, arm_id, model_pair_id, target_checkpoint_sha256, drafter_checkpoint_sha256, scheme, calibration_recipe, calibration_seed, evaluation_seed, evaluation_repeat, hardware_id, backend_id, emulation, config, category, subcategory, subset_manifest_sha256, comparison_manifest_sha256, concurrency, load_strategy, target_rate, num_speculative_tokens, decoding_manifest_sha256, warmup_manifest_sha256, calibration_manifest_sha256, environment_manifest_sha256, run_order, status, reason, raw_artifact_uri, provenance_uri` |
| `acceptance_counts.csv` — one measured counter interval per run | `run_id, measurement_interval_id, interval_start, interval_end, draft_events, proposed_draft_tokens, accepted_draft_tokens, status, reason`                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `position_counts.csv` — one position per run interval           | `run_id, measurement_interval_id, draft_position, accepted_at_position, draft_events, status, reason` (display position is 1-based)                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `performance.csv` — one measured interval per run               | `run_id, measurement_interval_id, measured_wall_seconds, output_tokens_successful, requests_expected, requests_successful, requests_failed, requests_cancelled, throughput_output_tokens_per_s, request_latency_median_ms, ttft_median_ms, token_weighted_request_mean_itl_median_ms, guidellm_output_tps_median, metric_definition_version, status, reason`                                                                                                                                                                                                                        |

| `contrasts.csv` — explicit matched comparisons                  | `contrast_id, comparison_round_id, arm_run_id, reference_run_id, contrast_type, metric, value, unit, status, reason` (pooled contrasts may point to aggregate IDs whose memberships are explicit)                                                                                                                                                                                                                                                                                                                                                                                   |

| `aggregate_members.csv` — reproducible membership               | `aggregation_id, run_id, measurement_interval_id, aggregation_method, coverage_manifest_sha256`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

Identity manifests pin actual revisions, versions, patches, device configuration, kernel/backend flags, module inventory, checkpoint hashes, calibration counts/token budgets, overlap report, cache storage precision, dataset preparation and warm-up settings. Preserve the historical cache's missing original-target-weight-hash limitation. A blank calibration seed is correct for BF16 and target-only references. Target-only drafter identity/acceptance is explicitly not applicable. Qualitative subcategory may be blank. Concurrency-driven tests must not pretend their target rate is an arrival-rate setting.

Derived values must agree with retained raw counts. Validate full expected membership, all three repeats, unique primary keys, source artifact checksums, ratio denominators, matching intervals, and reference matches before plotting. Those checks belong to the eventual implementation; this throwaway prototype introduces no production plotting code.

Export each figure as vector PDF and SVG plus a 200–300 dpi PNG; archive the CSV tables, metric/schema definitions, manifests, raw measurements, plotting command/version, provenance files and patches together. Link large provenance bundles and their checksums rather than embedding them in issue bodies. The prototype includes PNG/PDF/SVG at 160 dpi for quick layout review; final publication uses the selected higher resolution.

Rebuild: `python local/drafter-quant/wayfinder/plot-prototype/prototype.py`. Open `index.html` (variants `?variant=A`, `?variant=B`, `?variant=C`) or view the exported images directly. Python, NumPy and Matplotlib are required. This proposal remains open until the human chooses layouts, aggregation/metric rules and publication contract.
