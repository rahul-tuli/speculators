## Recipes and compatibility

- FP8 Block uses `model_free_ptq(scheme="FP8_BLOCK")` from llmcompressor. The installed compressed-tensors preset encodes static FP8 weights in 128 × 128 blocks and dynamic activation groups of 128. It needs no calibration data. Its H100 vLLM load and one-request smoke passed with `FlashInferFp8DeepGEMMDynamicBlockScaledKernel`.
- Both NVFP4 GPTQ arms use `GPTQModifier` with the same NVFP4 W4A4 configuration. The ordinary arm selects `nvfp4_expanded_mse` for weight scales. IMatrix selects `nvfp4_expanded_imatrix` with `strict: true`, so a missing activation observation fails instead of silently using ordinary MSE. The BasicPipeline calibrates the actual drafter forward and invokes GPTQ at sequential epoch end, but does not propagate compression error between layers. All four final GPTQ exports audited 36 compressed modules and zero RTN fallbacks.
- llmcompressor's normal AutoConfig probe does not know `model_type="speculator_model"`. The quantizer loads the speculator with `SpeculatorModel.from_pretrained`, skips that probe for this known BF16 source, keeps `_name_or_path` empty to protect the exported quantization config, and unwraps the compiled forward for calibration. Tokenizer files are restored byte-for-byte from the pinned target snapshot after `transformers.save_pretrained` rewrites ByteLevel metadata.
- The installed source revisions recorded in each run are llmcompressor `0349b68f4a7c5b0b535596df8e8d171911c8acee` and compressed-tensors `a2a210e9001d6ac45b6f294f8a66a87384c7da55`.

Each checkpoint contains `quant_run_manifest.json`, `quant_command.txt`, `source/` copies with SHA-256 hashes, the source model's training command, `recipe.yaml` where applicable, a calibration manifest, and `checkpoint_complete.json`. GPTQ exports additionally contain `gptq_audit.json` and `run_status.json`. The 0.01 ordinary Gaussian audit was reconstructed from its completed log and export; its source bundle was copied after the run and the backfill note is in its command/manifest. The IMatrix Gaussian and initial 0.01 real runs preserve launch-time source bundles. The IMatrix Gaussian has a separate post-export tokenizer restoration record.

Both 0.1 real Python quantizers completed successfully and all 166 exported tensors passed verification. Their Bash wrappers returned exit code 2 after printing `[done]` because the shared wrapper file was edited while those long-running shells were active. `wrapper_run.log` and `wrapper_completion_anomaly.json` in each output preserve the shell result, the distinct launch/current wrapper hashes, and the completed quantizer evidence. The model weights were not changed by this provenance annotation.

The resumable production entrypoint is `bash local/drafter-quant/scripts/run_added_quantizations.sh all` from the workspace root. It retains completed 0.01 Gaussian outputs, uses the pinned source/tokenizer, and selects 0.1 only for the real GPTQ outputs. It refuses nonempty partial output directories and skips only checkpoints with completion markers, manifests, and safetensors.
